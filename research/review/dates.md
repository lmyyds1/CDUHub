## 0. 一句话结论

日期字段本身**语法全对**（0 条非法日期、0 条非法日历日、0 条与 dateText 年份不一致），问题全部集中在**「取不到」和「取错源」**：

1. **取不到**——3528 篇 `date` 为空（占 21.1%），根因是爬虫给每个来源的详情页补全预算被硬编码为 **`detailBudget = 12`**（`internal/crawler/crawler.go:27`），而 20 个来源需要补全的条数远超 12，合计 **3178 篇**超出预算未补全。
2. **取错源**——列表页把日期渲染在**兄弟节点/拆分节点**里（`<span>09.17</span><font>2021</font>`、`<span>14</span><br>2026-10`），`dateValue()` 只能看到其中一半，于是产出 1224 条「月日无年份」和 796 条「乱序 `14 2026-09`」。
3. **取错语义**——标题/正文里的**截止日、有效期、施行日**被判成发布日：已验证 14 条真实错判（图书馆 3、期刊中心 3、信息网络中心 6、机械工程 1、张澜 1），其中 2 条直接跑到未来。

## 4. 标题日期污染交叉检查

### 4.1 数字基线

- 标题含**严格意义完整日期**（`19xx/20xx` + 月 + 日）：**634 条**。
- 用宽松正则（去掉边界前瞻）得 **638 条**——多出的 4 条全是**区间表达式**被误配：`部、省、市哲学社会科学优秀成果获奖情况（2012.01-2020.05）` 之类（马克思主义学院 4 条）。这说明「区间/期间」写法本身就是一个独立的误判模式。
- 其中 `date` 恰好等于标题里的日期：**66 条**。
- 标题含完整日期但 `date` 是另一天：**106 条**（例：`https://law.cdu.edu.cn/info/1092/7014.htm` 标题写「2026年7月27日至31日…」，date=`2026-08-02`，详情页「发布时间：2026年08月02日」——**正文事件日，不该改**）。
- `date` 为空但标题尾部带完整日期：**461 条**（商学院 439 + 机械工程 0 + 音乐与舞蹈 8 + 图书馆 6 + 保卫处 8）。

### 4.2 「真污染」还是「源站把日期写进标题」——判定口径

对 66 条逐条看**日期在标题里的语义角色**和**详情页标签**：

| 位置分布 | 条数 | 来源 | 语义 | 判定 |
|---|---:|---|---|---|
| 标题**后缀**（日期在末尾） | 44 | 机械工程学院 35、音乐与舞蹈学院 9 | 列表行把 `2026-09-14` 拼在标题后 | **日期正确**，只是标题脏（`dateText` 乱序是同一根因） |
| 标题**前缀/方括号**（日期在开头） | 5 | 张澜学院 3、音乐与舞蹈学院 2 | 源站列表就把日期前置 | **日期正确** |
| 标题**内嵌**且语义是「有效期/公告时间/更新」 | 17 | 图书馆 3、教学质量管理办公室 8、张澜学院 2、继续教育 2、海外教育 1、研究生处 1 | 「（试用有效期：即日起--2026年12月31日）」「【公告时间】2026年09月08日」「（2025年9月5日更新）」 | **图书馆 3 条 = 真污染**；shpg 8 条详情页「发布时间」与标题「公告时间」同日 → **日期正确**；其余 6 条同日 → **日期正确** |
| 合计 | 66 | | | **真污染 3 / 标题脏但日期对 63** |

**落地成代码规则（可直接写进 dateValue 的上游）**：

1. 若日期片段前 8 个字符内出现 `有效期|截止|报名时间|活动时间|举办时间|会议时间|考试时间|结束时间|施行|公布|实施|更新` → **不得**用作发布日，优先取页面 `发布时间/发布日期` 标签。
2. 若日期片段位于标题**末尾**且标题前文（去掉该片段）仍 ≥ 6 个汉字 → 判为「列表日期被拼进标题」，可用作 `date` 但**要同时从标题里剥掉**（`parser.go:647-649` 的 trim 要用归一化后的 ISO 串再试一次）。
3. 若日期片段是 `YYYY.MM-YYYY.MM` / `YYYY-MM—YYYY-MM` 形态的区间 → 直接丢弃（4 条马克思主义学院样本）。
4. 只有当「标题日期 == 详情页发布时间」时才允许把标题日期写进 `date`；否则一律以详情页标签为准。

### 4.3 抽样结论

- 66 条里 **63 条日期是对的**，所以「标题含日期」**不能**作为污染判据单独使用；必须叠加「语义角色」或「详情页对照」。
- 真正需要修的 3 条全部来自**图书馆试用数据库**栏目，且形态完全一致（标题 → 有效期），是**可枚举、可一次性修干净**的一类。
- 461 条「空 date 但标题尾部带日期」是**零成本回收**：不需要再抓网络，`title` 里就有 `2026-03-13`，且已用详情页抽样 10/10 验证该日期就是页面发布时间（如 `https://bs.cdu.edu.cn/info/1043/12810.htm` 标题 `…专题班会 2026-03-13`，详情页 `发布时间：2026年03月13日`）。

### 5.3 修法建议（针对 `99.99` 这一类，最小改动）

1. `dateInNode()`：把「`class` 命中 `date/time`」扩展为「节点文本含 `\d{1,2}[./-]\d{1,2}` 且**父/兄弟节点**含 `(19|20)\d{2}`」——即 `sspan` + 相邻 `font`、`tx-date` 的 `span`+`b`、`txt-date` 的 `span`+`br` 三种模板。
2. `dateValue()` 增加「月日 + 兄弟年份」合成路径：先跑 `partialDateRE` 拿到 `09.17`，再在上层节点文本里找唯一 4 位年份，合成 `2021-09-17`；若上层出现多个年份（如标题里的「2022年硕士」），用**距离最近的兄弟节点**而不是整段文本。
3. 跨年边界：12 月/1 月的月日型必须靠年份而不是 `time.Now()` 推断——本次数据里 `https://ftva.cdu.edu.cn/info/1216/2063.htm` 是 `01.19` → 2021-01-19（列表年 2021），若按采集时间（2026-09）反推会算成 2027，**跨年边界是必踩的坑**，建议直接禁止「用采集时间推年份」。

## 6. 建议优先修复的 3 类模式（带证据）

### 第 1 类：详情页补全预算 `detailBudget = 12` 严重不足（影响 3528 篇 + 3178 篇超额）

- 证据：`internal/crawler/crawler.go:27` `detailBudget = 12`；`:275-277` 直接截断候选。
- 表现：**商学院 451 篇里恰好 12 篇有日期、实验室与设备管理处 84 篇里恰好 12 篇、音乐与舞蹈学院 628 篇里恰好 12 篇**——三个来源三倍的巧合，只可能是同一个截断点。
- 量级：20 个来源的「需要补全条数 > 12」，合计 **3418 篇需要补全、3178 篇被预算截掉**。
- 抽样验证：这些被截掉的记录，详情页 **86/86 都有完整 `发布时间`**（分层抽样里所有 `date` 为空且页面有标准日期标签的页面全部命中，见 §2 抽样表「页面有日期而 `date` 为空」列）。
- 修法：预算改为「按需 + 并发上限」而不是「每来源固定 12」；或至少在 `date==""` 且 `source.ArticleCount` 大时提高到「该来源缺失条数」的 80%。

### 第 2 类：列表页日期在兄弟/拆分节点（1224 条月日型 + 796 条乱序）

- 证据（三种模板，全部实抓）：
  - `https://msys.cdu.edu.cn/zsjy/yjszs1.htm` → `<span class="sspan">09.17<font>2021</font></span>`
  - `https://jxgc.cdu.edu.cn/index/tzgg.htm` → `<div class="pull-left txt-date text-center"><span>14</span><br>2026-10</div>`
  - `https://journal.cdu.edu.cn/xwgg.htm` → `<div class="tx-date"><span>10-21</span><b>2026</b></div>`
  - `https://bwc.cdu.edu.cn/` → `<a …>标题</a></div><div …><a …>07-23</a>`
- 表现：984 条 `99.99`（美术与设计 630 / 影视与动画 354）、171 条 `99-99`、39 条 `9/9`、30 条中文月日 —— **全部 date 为空**；另有 796 条 `date` 正确但 `dateText` 乱序、标题残留日期。
- 修法：给 `dateValue` 加「月日 + 邻近年份」合成；`dateInNode` 从「看 class」改成「看结构」（`span+font`、`span+b`、`span+br` 三种）；`parseArticles` 的 trim 改用 ISO 归一化串。
- 直接收益：一次性消掉 1224 条（占缺失的 35%）+ 796 条展示错误 + 前 2 大异常来源（98%/96%）的大部分。

### 第 3 类：把「有效期/截止/施行/更新」日期当发布日（12 条已核实错判，含未来日期 2 条，最大偏差 14 年）

> 全部 14 条已核实错判的构成：本类 12 条（图书馆 3 + 期刊中心 3 + 信息网络中心 6）+ §2.B2b 零散 2 条（news 差 1 天、张澜差 1 周）。

- 证据：
  - `https://lib.cdu.edu.cn/info/1057/1571.htm`：`date=2026-12-31`，页面「发布时间：2022-05-16」，标题「（试用有效期：即日起--2026年12月31日）」
  - `https://lib.cdu.edu.cn/info/1057/1540.htm`：`date=2026-12-31`，页面「发布时间：2022-03-01」
  - `https://lib.cdu.edu.cn/info/1057/1543.htm`：`date=2026-03-01`，页面「发布时间：2022-03-08」
  - `https://journal.cdu.edu.cn/info/1058/1332.htm`：`date=1998-04-01`，页面「时间：2015-12-02」，正文「2005年9月30日…公布 自2005年12月1日起施行」
  - `https://nic.cdu.edu.cn/info/1038/1132.htm`：`date=2000-12-28`，页面「发布日期:2014-09-19」
  - `https://nic.cdu.edu.cn/info/1038/1134.htm`：`date=2000-09-20`，页面「发布日期:2014-09-19」
- 判据可复用：**本类 12 条里 11 条**满足「日期片段前 8 字内出现 `有效期|截止|施行|公布|公告时间|更新`」或「正文/`meta description` 优先于页面 `发布日期` 标签」（唯一例外是 `1334` 的正文无日期、由列表摘要污染）。
- 修法：优先级顺序改为 **`<time>发布时间/发布日期` 标签 > `pubdate` meta > 列表页结构化节点 > 标题/正文日期**（当前 `detailMetadata()` 先扫 `meta` 再扫正文，`发布时间` 与正文谁先命中取决于 DOM 顺序，不可控）。

## 7. 复现方式

```powershell
# 结构化报告（人类可读 + JSON）
python -X utf8 research/review/date-scan.py
python -X utf8 research/review/date-scan.py --json out.json
python -X utf8 research/review/date-scan.py --section sources
python -X utf8 research/review/date-scan.py --limit 100
```

脚本只读 `data/snapshot.json`，输出到 stdout（`sys.stdout.reconfigure(encoding="utf-8")`），支持 `--json` / `--section all|sources|titles` / `--limit`。新增的检查项：`dateText_garbled_order`、`no_date_but_title_has_date`、`nav_control_as_article`，来源表新增「dateText 全空 / 乱序 / 标题可回填 / 异常合计 / 异常率」列。

网络复核可复用文中的 Go 抓取思路（`net/http` + `User-Agent: Mozilla/5.0`，`GOCACHE` 指向工作区）：

```powershell
$env:GOCACHE="$PWD\.cache\go-build"; go run <抓取程序>.go
```
